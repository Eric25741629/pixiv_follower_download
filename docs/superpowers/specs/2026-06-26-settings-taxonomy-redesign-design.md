# 設定頁分類與文案重整規格

日期：2026-06-26
狀態：已與使用者確認方向，本文為實作前 spec

## 目標

把目前設定頁從「功能堆疊式」改成「依設定性質分組」的資訊架構，降低掃讀成本，讓使用者更容易回答三個問題：

1. 這個設定是在管哪一類事情？
2. 我現在要改的欄位應該去哪一區找？
3. 開關或欄位改下去，會影響下載流程的哪一段？

這次只重整設定頁的分類、區塊命名、欄位文案與說明文字；**不改設定 schema、不改儲存邏輯、不改功能行為**。

## 已確認的範圍決策

1. 分類方式採 **依設定性質分組**，不是依執行流程分組。
2. 可以增加大區塊數量，不必維持目前 5 區。
3. 除了重排欄位，**分類名稱與欄位說明文字都要重寫**。
4. 本輪輸出是 spec，不進行實作。

## 現況問題

目前 `settings_view.py` 的 5 區布局有三個主要問題：

1. **同一區混入不同性質的設定。**
   `下載輸出` 內同時有下載路徑、資料夾分類、檔名規則、缺值過濾、tag 整理、JXL 轉檔，使用者需要先理解內部邏輯才能找到欄位。
2. **部分欄位被放在錯誤心智模型下。**
   例如 `無 tag 不下載` / `無時間不下載` 本質上是篩選或缺值處理，不是輸出設定。
3. **文案偏技術視角。**
   幾個欄位名稱描述的是實作機制，而不是使用者目的；說明文字也不夠一致，有些欄位只有 label，沒有交代影響範圍。

## 非目標

- 不新增新的設定鍵或 UI 控制項
- 不更動 autosave / 手動儲存規則
- 不拆成多頁設定頁
- 不調整 `SettingsStore` 的 section 結構
- 不處理視覺主題或 UI 元件庫重構

## 採用方案：8 區資訊架構

設定頁改成以下 8 個主區塊，順序固定如下：

1. `帳號與登入`
2. `連線與瀏覽識別`
3. `作品來源與抓取策略`
4. `下載位置與資料夾分類`
5. `檔名與時間戳`
6. `標籤整理與缺值處理`
7. `作品篩選條件`
8. `格式轉換、效能與自動化`

設計原則：

- 先放「進入系統所需」設定，再放「抓什麼」，最後放「怎麼存、怎麼跑」。
- 一個主區塊只回答一種類型的問題。
- 每個主區塊都要有一段 1 句說明，先講用途，再講影響範圍。

## 詳細規格

### 1. 帳號與登入

**區塊說明**

`設定 Pixiv 登入資訊。這些欄位主要影響登入、身分識別與需要帳號的抓取流程。`

**收納欄位**

- `帳號`
- `密碼`
- `User ID`

**文案規則**

- 保留 `User ID` 這個詞，但區塊說明補足用途，不再假設使用者知道它的作用。
- 這一區不混入 UA / Proxy，避免把「登入資料」和「連線策略」混在一起。

### 2. 連線與瀏覽識別

**區塊說明**

`調整請求時使用的瀏覽器識別與代理連線。只有在相容性、封鎖或網路路徑需要調整時才建議修改。`

**小節與欄位**

1. `瀏覽器識別`
   - `User-Agent`
   - `重新偵測 Chrome`
   - 狀態提示文字
2. `代理連線`
   - `Proxy 列表（每行一個）`
   - `測試全部 Proxy`
   - Proxy 測試結果列表

**文案調整**

- `User-Agent` 小節說明：
  `未設定時會使用內建隨機 UA。只有遇到站點相容性問題時才需要手動指定。`
- `Proxy` 小節說明：
  `每行一組 proxy，支援 http://、https://、socks5://。留空表示直接連線。`

### 3. 作品來源與抓取策略

**區塊說明**

`決定作品從哪裡來，以及步驟 2 到步驟 4 以什麼方式查詢與下載。`

**收納欄位**

- `作品來源`
- `追隨範圍`
- `收藏範圍`
- `查到即下載（合併步驟 3、4）`
- `同時處理作品數`
- `依作者順序下載（同作者連續）`
- `下次掃描時忽略 30 天跳過規則（一次性）`

**欄位改名**

- `邊查邊下（查到即下載，合併步驟三、四）`
  -> `查到即下載（合併步驟 3、4）`
- `邊查邊下並發數（1=循序）`
  -> `同時處理作品數`
- `強制重新掃描全部畫家（忽略30天，一次性）`
  -> `下次掃描時忽略 30 天跳過規則（一次性）`

**補充說明文字**

- 來源小節說明：
  `抓追隨會先整理畫師清單；抓我的收藏會以你按過愛心的作品作為來源。`
- `同時處理作品數` tooltip / note：
  `1 代表逐件處理。實際並發數仍會受有效 Cookie 數與待處理量限制。`
- `下次掃描時忽略 30 天跳過規則（一次性）` tooltip / note：
  `適合補齊作者資料或強制重掃。執行一次步驟 2 後會自動關閉。`

### 4. 下載位置與資料夾分類

**區塊說明**

`決定檔案要存到哪裡，以及是否依作者或作品屬性自動分資料夾。`

**收納欄位**

- `下載路徑`
- `依作者 ID 建立子資料夾`
- `R-18 作品分類資料夾`
- `R-18G 作品分類資料夾`
- `AI 生成作品分類資料夾（關閉後下載到一般路徑）`

**補充說明文字**

- 區塊 note：
  `啟用後會在下載目錄下建立對應子資料夾；關閉時則直接存到一般下載路徑。`

### 5. 檔名與時間戳

**區塊說明**

`控制下載後的命名規則與檔案時間。時間戳會隨每張圖片自動遞增。`

**收納欄位**

- `檔名範本`
- `下載時間戳起點`
- `下載檔案時間設為時間戳（mtime）`

**補充說明文字**

- `檔名範本` 說明：
  `可用佔位符：{pid} {page} {ext} {tag} {hashtag} {timetag} {date} {time}。留空時使用預設命名規則。`
- `下載時間戳起點` 說明：
  `供檔名中的 {timetag} 與檔案修改時間使用；每下載一張圖片會自動加 1 秒。`
- `下載檔案時間設為時間戳（mtime）`
  保留原意，但名稱補上括號，讓進階使用者知道實際改的是檔案 mtime。

### 6. 標籤整理與缺值處理

**區塊說明**

`控制 tag 如何進入檔名，以及作品缺少必要資訊時是否直接跳過。`

**收納欄位**

- `作品沒有 tag 時跳過`
- `作品沒有發佈時間時跳過`
- `Tag 過濾括號內容`
- `Tag 過濾裝飾符號與 emoji`

**欄位改名**

- `無 tag 不下載`
  -> `作品沒有 tag 時跳過`
- `無時間不下載`
  -> `作品沒有發佈時間時跳過`

**補充說明文字**

- 區塊 note：
  `這一區只處理「檔名素材是否可用」與「缺值是否略過」，不處理喜歡數或黑白名單篩選。`
- `Tag 過濾括號內容` tooltip 保留現有規則說明
- `Tag 過濾裝飾符號與 emoji` tooltip 保留現有規則說明

### 7. 作品篩選條件

**區塊說明**

`決定哪些作品應該保留、略過或重新抓取資料。`

**收納欄位**

- `隱藏追蹤`
- `過濾 GIF`
- `最低讚數（一般）`
- `最低讚數（R-18）`
- `重抓上限（天數，0 = 關閉）`
- `禁止 tag`
- `必須 tag`

**補充說明文字**

- 區塊 note：
  `這一區影響作品是否通過條件，不影響下載位置、檔名或執行速度。`
- `重抓上限（天數，0 = 關閉）` 補充說明：
  `新作品在這個天數內可重新抓取 meta，以更新喜歡數並重新判斷是否符合條件。`

### 8. 格式轉換、效能與自動化

**區塊說明**

`控制下載後轉檔、執行速度與自動執行行為。建議先使用預設值，確認穩定後再調整。`

**小節與欄位**

1. `JXL 轉檔`
   - `啟用 JXL 轉檔`
   - `cjxl.exe 路徑`
   - `刪除原檔`
   - `跳過 GIF 轉檔`
   - `Effort（1-9）`
2. `速度控制`
   - `每個帳號的冷卻秒數`
   - 冷卻滑桿
   - `同 PID 頁間等待（秒）`
   - `未使用 Cookie 的請求等待（秒）`
   - `以單執行緒處理作品`
3. `排程`
   - `啟用排程（定時自動 Run All）`
   - `排程方式`
   - `每日時間`
   - `間隔（小時）`

**欄位改名**

- `單帳號冷卻秒數`
  -> `每個帳號的冷卻秒數`
- `免 Cookie 請求等待（秒）`
  -> `未使用 Cookie 的請求等待（秒）`
- `單執行緒 PID 模式`
  -> `以單執行緒處理作品`

**補充說明文字**

- `JXL 轉檔` 小節說明：
  `用於下載完成後的格式轉換。未設定 `cjxl.exe` 時，會使用預設搜尋路徑。`
- `速度控制` 小節說明：
  `數值越小，整體速度越快，但也越容易接近站點風控邊界。`
- `排程` 小節說明：
  `啟用後會在背景依設定時間自動觸發 Run All。`

## 欄位重新分組對照

下列欄位需要從現有主區塊移動到新的主區塊：

- 從 `下載輸出` 移出到 `標籤整理與缺值處理`
  - `無 tag 不下載`
  - `無時間不下載`
  - `Tag 過濾括號內容`
  - `Tag 過濾裝飾符號與 emoji`
- 從 `下載輸出` 移出到 `格式轉換、效能與自動化`
  - 全部 JXL 控制項
- 保留在 `作品篩選條件`，但補強文案
  - `隱藏追蹤`
  - `過濾 GIF`
  - 喜歡數與 tag 黑白名單
- `作品來源`、`追隨範圍`、`收藏範圍` 與查到即下載 / 依作者順序 / 一次性重掃
  集中到 `作品來源與抓取策略`

## 版面與互動規則

1. 仍使用 `c.section(...)` 對應的 `ExpansionTile` 結構，不新增分頁或側欄。
2. 每個主區塊保留可折疊特性，但預設展開行為維持現狀。
3. 可以在主區塊內保留 `subhead`，但每個 `subhead` 只服務同一語意，不再混放不同性質欄位。
4. `開關即時 autosave；文字/滑桿需按儲存設定` 的整體儲存規則不變。
5. `Proxy 測試結果`、`Chrome 偵測狀態`、`冷卻提示文字` 等動態訊息仍保留在原控制項附近。

## 實作落點

這份 spec 對應的主要修改檔案預期為：

- `app/gui/views/settings_view.py`
- `tests/test_settings_view_layout.py`

如文案抽取或 tooltip 組裝需要微調，允許同步更新：

- `app/gui/views/settings_handlers.py`

但不得為了這次分類重整去改 `SettingsStore` schema 或核心執行緒行為。

## 驗收標準

1. 設定頁主區塊由 5 區改為 8 區，順序與命名符合本 spec。
2. 現有所有設定控制項都仍存在，沒有遺漏。
3. `無 tag 不下載`、`無時間不下載` 不再出現在輸出類區塊。
4. JXL 控制項不再和下載路徑 / 檔名規則混在同一語意段落。
5. 每個主區塊都有一段用途說明，且文案以使用者目的為主，不只描述技術機制。
6. 測試更新後，`tests/test_settings_view_layout.py` 至少驗證新的主區塊標題順序。
7. 這次調整不改任何設定 key、section 名稱或存檔格式。

## 後續實作建議

實作時應先做最小範圍調整：

1. 先重排 `build()` 內 section 順序與內容。
2. 再改 labels / notes / subheads / tooltip 文案。
3. 最後更新 layout 測試，確認新 8 區標題順序。

不在這次 spec 內要求：

- 文案 i18n 抽離
- 設定搜尋功能
- 進階/基本模式切換
- 多頁籤設定中心
